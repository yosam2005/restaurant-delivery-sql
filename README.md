\# Restaurant Delivery Data Analysis Using PostgreSQL



\## Project Overview



This project analyzes restaurant delivery data using PostgreSQL and SQL. The database represents a food delivery platform that connects customers, restaurants, orders, items, and deliveries across multiple cities and countries.



The project focuses on using a relational database to organize, clean, validate, and analyze operational data. SQL queries are used to examine restaurant revenue, order activity, customer ordering patterns, cuisine distribution, and order completion rates.



The goal of the project is to demonstrate practical PostgreSQL skills, including database design, data loading, data cleaning, table relationships, joins, aggregations, and business-focused SQL analysis.



\## Business Problem



A global food delivery platform needs to understand its customers, restaurants, orders, and delivery activity across different cities and countries. Without organized data and reliable analysis, it can be difficult to identify revenue patterns, understand customer ordering behavior, and evaluate order performance.



This project uses a relational PostgreSQL database to answer business questions related to restaurant revenue, order activity, customer behavior, cuisine distribution, and order completion.



\## Objectives



The main objectives of this project are to:



\* Analyze revenue generated by each restaurant.

\* Examine the number of orders across cities and cuisine types.

\* Analyze customer ordering frequency by city.

\* Measure order completion rates across different cities.

\* Compare recorded order totals with totals calculated from individual order items.

\* Identify data-quality issues that could affect business analysis.



\## Database Design



The project uses a relational PostgreSQL database named `restaurant\_delivery\_db`. The database is organized into seven related tables that represent customers, restaurants, orders, order items, deliveries, cities, and countries.



\### Tables



| Table         | Purpose                                                                           |

| ------------- | --------------------------------------------------------------------------------- |

| `countries`   | Stores country information.                                                       |

| `cities`      | Stores cities and their associated countries.                                     |

| `customers`   | Stores customer information and the city where each customer is located.          |

| `restaurants` | Stores restaurant information, cuisine type, and location.                        |

| `orders`      | Stores customer orders, restaurants, order dates, amounts, and order status.      |

| `items`       | Stores the individual items included in each order, including quantity and price. |

| `deliveries`  | Stores delivery dates and delivery status for orders.                             |



\### Table Relationships



The database uses primary keys and foreign keys to connect the tables:



\* A \*\*country\*\* can have multiple cities.

\* A \*\*city\*\* can have multiple customers and restaurants.

\* A \*\*customer\*\* can place multiple orders.

\* A \*\*restaurant\*\* can receive multiple orders.

\* An \*\*order\*\* can contain multiple items.

\* An \*\*order\*\* can have an associated delivery record.



These relationships allow SQL queries to combine information across multiple tables using `JOIN` operations.



\## Data Cleaning and Validation



Before performing the analysis, the data was reviewed for formatting and consistency issues. SQL was used to identify and correct problems that could affect the accuracy of the analysis.



\### Data Cleaning



The following cleaning steps were performed:



\* Removed leading and trailing whitespace from city, customer, and restaurant names.

\* Standardized multiple spaces within customer and restaurant names.

\* Verified that country, city, customer, restaurant, order, item, and delivery records were properly loaded.

\* Checked order statuses and item-level data for consistency.

\* Verified relationships between tables using primary and foreign key fields.



\### Data Validation



Order totals were validated by calculating the expected order amount from the individual items:



`quantity × price`



The calculated totals were then compared with the recorded order totals stored in the `orders` table.



This validation identified inconsistencies in several orders, demonstrating the importance of performing data-quality checks before using database information for business analysis.



\## SQL Analysis



SQL queries were developed to answer business questions related to restaurant revenue, customer activity, order performance, and data quality.



\### 1. Order Total Validation



Calculated the total value of each order using:



`quantity × price`



The calculated amount was compared with the recorded order total to identify discrepancies and potential data-quality issues.



\### 2. Revenue by Restaurant



Calculated total revenue for each restaurant by joining orders, restaurants, and item-level data.



This analysis helps identify which restaurants generated the highest revenue within the available dataset.



\### 3. Orders by City and Cuisine



Analyzed order activity by city and cuisine type to understand how orders were distributed geographically and across different restaurant categories.



\### 4. Orders and Customers by City



Calculated:



\* Total orders

\* Number of unique customers

\* Average orders per customer



This provides a basic view of customer ordering activity across cities.



\### 5. Order Completion Rate



Calculated the number of completed orders and the completion rate for each city.



This helps evaluate order performance and identify differences in completion activity across locations.



The complete SQL analysis is available in \[`sql/03\_analysis\_queries.sql`](sql/03\_analysis\_queries.sql).



\## Key Findings



The SQL analysis produced several findings from the available project dataset:



\* \*\*Revenue varied across restaurants\*\*, with Desert Grill generating the highest calculated revenue at \*\*$84.25\*\*, followed by Curry House at \*\*$37.50\*\* and Pizza Palace at \*\*$25.50\*\*.

\* \*\*Order-total discrepancies were identified\*\* when recorded order totals were compared with totals calculated from individual order items. Four of the five orders had differences between the recorded and calculated amounts.

\* \*\*Order activity was evenly distributed across the five cities\*\* in the current dataset, with one order associated with each city.

\* \*\*Customer ordering frequency was 1.00 order per customer\*\* in each city because each customer placed one order in the available dataset.

\* \*\*Order completion rates differed by city\*\*. Riyadh, Mumbai, and New York had completed orders, while London and Toronto had pending orders at the time represented in the dataset.

\* The analysis demonstrates how SQL can be used to \*\*validate data, identify inconsistencies, summarize business activity, and support data-driven decision-making\*\*.

\## How to Run the Project



\### Prerequisites



To run this project, you will need:



\* PostgreSQL

\* A PostgreSQL client such as `psql` or pgAdmin

\* Git, if cloning the repository from GitHub



\### Setup



1\. Clone the repository:



```bash

git clone https://github.com/yosam2005/restaurant-delivery-sql.git

```



2\. Open PostgreSQL and create a database named:



```text

restaurant\_delivery\_db

```



3\. Run the table-creation script:



```text

sql/01\_create\_tables.sql

```



4\. Load the CSV data using:



```text

sql/02\_insert\_data.sql

```



5\. Run the analysis queries:



```text

sql/03\_analysis\_queries.sql

```



The analysis script can then be used to validate the data and answer the business questions described in this project.
